NG-nfs-handler 0.9 beta -- handler per filesystem NFS su AmigaOS
=================================================================

NG-nfs-handler monta le condivisioni NFS di un server Linux (o di qualsiasi
server NFSv3) come un normale volume AmigaDOS. È un handler DOS da mettere
in L: e montare con una mountlist standard; si smonta con il comando
NFSDismount.

  - NFSv3 su TCP (libnfs 8.1.0 integrata, nessuna libreria esterna)
  - lettura e scrittura: file, directory, rename, delete, protezioni, date,
    hard link e soft link relativi
  - nomi senza distinzione tra maiuscole e minuscole, come ogni filesystem
    Amiga (disattivabile)
  - conversione dei nomi Latin-1 <-> UTF-8
  - notifiche DOS (StartNotify) tramite polling
  - mount "lazy": la rete viene contattata al primo accesso, quindi il
    volume si può montare al boot prima che lo stack TCP/IP sia attivo
  - riconnessione automatica quando il server si riavvia

Provato su: ROM AmigaOS 3.1 + 3.9 (Vampire V4, Roadshow 4.364), AmigaOS 3.9
in Amiberry (emulazione bsdsocket).


1. Requisiti
------------

  - AmigaOS 3.1 o successivo, 68020 o superiore
  - uno stack TCP/IP con bsdsocket.library (Roadshow, AmiTCP, Miami,
    Genesis, oppure l'emulazione bsdsocket di UAE/Amiberry)
  - un server NFS con NFSv3 su TCP attivo (nfs-kernel-server di Linux lo
    è di default)


2. Installazione
----------------

  Copy L/nfs-handler     L:
  Copy C/NFSDismount     C:

Poi copia la mountlist di esempio Storage/DOSDrivers/NFS0 in
DEVS:DOSDrivers/ (montaggio al boot) oppure in SYS:Storage/DOSDrivers/
(montaggio a mano) e modifica la riga Startup (vedi sezione 4).

Montaggio e uso:

  Mount NFS0:
  Dir NAS:

NFS0: è il device, NAS: il nome del volume (opzione VOLUME=).
Per smontare:

  NFSDismount NFS0:

NON usare "Assign NFS0: DISMOUNT": su AmigaOS 3.x toglie il device senza
avvisare l'handler. nfs-handler se ne accorge e si chiude da solo quando
nessuno usa più il volume, ma il modo pulito è NFSDismount.


3. Mountlist di esempio
-----------------------

  Handler   = L:nfs-handler
  StackSize = 32768
  Priority  = 5
  GlobVec   = -1
  Activate  = 1
  Startup   = "SERVER=192.168.1.100 EXPORT=/export/amiga VOLUME=NAS UID=1000 GID=1000"

La stringa Startup DEVE essere tra virgolette (altrimenti Mount la
rifiuta). Lascia Priority = 5: l'handler deve avere priorità più alta della
Shell che lo monta.


4. Opzioni di Startup
---------------------

  SERVER=host        nome o indirizzo IP del server NFS (obbligatorio).
                     Usa l'IP se lo stack non ha un DNS configurato.
  EXPORT=/percorso   directory esportata dal server (obbligatorio)
  VOLUME=nome        nome del volume Amiga (default: nome del device)
  UID=n  GID=n       utente/gruppo inviati al server (AUTH_SYS);
                     default 65534 (nobody). I file creati appartengono a lui.
  CASE=INSENSITIVE   (default) "readme.txt" trova "README.TXT", e scrivere su
                     un nome esistente con maiuscole diverse sovrascrive il
                     file esistente invece di crearne un secondo
  CASE=SENSITIVE     solo nomi esatti (più veloce su directory enormi)
  CHARSET=LATIN1     (default) nomi UTF-8 sul server, Latin-1 su Amiga; i
                     caratteri fuori dal Latin-1 (e ':' '%') appaiono come
                     sequenze %XX, così ogni file resta raggiungibile
  CHARSET=RAW        nessuna conversione
  READONLY           monta in sola lettura
  SYNC=NO            (default) scritture UNSTABLE veloci, confermate al Close()
  SYNC=YES           ogni scrittura confermata subito (più lento, più sicuro)
  UMASK=022          maschera dei permessi per file/directory nuovi (ottale)
  RSIZE=16384        byte massimi per lettura NFS
  WSIZE=16384        byte massimi per scrittura NFS
  PAR=4              richieste di lettura/scrittura in parallelo per
                     pacchetto DOS (1-16)
  TIMEOUT=10         secondi prima che una richiesta NFS fallisca
  NOTIFYPOLL=4       secondi tra un controllo delle notifiche e l'altro
                     (0 = notifiche DOS disattivate)
  LOG=file           scrive un log di diagnosi (ogni pacchetto DOS, chiamate
                     NFS, tempi). Usa RAM:, non un volume di rete. Lento!


5. Configurazione del server (Linux)
------------------------------------

Esempio di /etc/exports:

  /export/amiga  192.168.1.0/24(rw,sync,no_subtree_check,all_squash,anonuid=1000,anongid=1000)

poi "exportfs -ra".

  all_squash,anonuid=,anongid=  ogni accesso dall'Amiga diventa un unico
                utente Linux: semplice e coerente con le opzioni UID/GID.
  insecure      serve SOLO se il client non può usare porte sotto la 1024.
                Gli stack Amiga veri possono; l'emulazione bsdsocket di
                UAE/Amiberry no (gira come utente normale): lì aggiungi
                "insecure".
  async         molto più veloce con tanti file piccoli (creazione,
                cancellazione), al prezzo di perdere le ultime modifiche se
                crasha il SERVER. Con "sync" (default) ogni operazione sui
                metadati aspetta il disco del server.

La directory esportata deve appartenere all'utente anonuid, altrimenti le
scritture falliscono con "protetto in scrittura".


6. Comportamento e limiti
-------------------------

  - Bit di protezione: R, W, E corrispondono ai bit dell'owner del modo
    Unix; D segue W. H, S, P, A e i commenti (filenote) vengono accettati e
    scartati.
  - Le dimensioni dei file sono a 32 bit su AmigaOS 3.x: i file oltre 2 GB
    appaiono da 2 GB e non si possono leggere oltre quel punto.
  - Soft link: si possono creare solo con bersaglio relativo. I link sul
    server vengono seguiti in modo trasparente (un link a una directory
    appare come una directory).
  - I lock sono locali: i lock esclusivi non sono visti dagli altri client.
  - DeleteFile() di un oggetto aperto o con lock fallisce con "oggetto in uso".
  - SYNC=NO: se il server si riavvia tra una scrittura e il Close() del
    file, gli ultimi dati scritti possono andare persi senza errore (il
    "write verifier" NFS non viene ancora controllato). Usa SYNC=YES se
    è importante.
  - Le notifiche funzionano a polling (NFS non ha notifiche di modifica).
    Le modifiche fatte tramite l'handler vengono notificate subito.
    Directory Opus aggiorna i suoi lister da solo.
  - I nomi con sequenze %XX si aprono normalmente da Workbench e Directory
    Opus; la Shell di AmigaOS 3.9 toglie i '%' dai nomi digitati.
  - Se il server si riavvia, l'operazione in corso in quel momento fallisce
    con "Nessun disco" (requester Riprova/Annulla): premi Riprova. I file
    aperti vengono riaperti da soli. Se il server è del tutto
    irraggiungibile, il primo accesso aspetta il timeout di connessione TCP
    dello stack.


7. Problemi comuni
------------------

  - Il mount fallisce / "Nessun disco": controlla la rete (ping al server),
    usa l'IP in SERVER=, verifica che NFSv3 su TCP sia attivo (su Linux
    "rpcinfo -p server" deve elencare nfs versione 3, tcp).
  - "Permesso negato" al mount: l'export non accetta l'indirizzo
    dell'Amiga, oppure serve "insecure" (emulatori).
  - Le scritture falliscono con "protetto in scrittura": la directory
    esportata non è scrivibile dall'utente anonuid/UID.
  - NFSDismount dice "oggetto in uso": qualcosa usa ancora il volume (una
    Shell con CD lì sopra, un lister di Directory Opus, un file aperto).
    Con LOG= il log elenca ogni lock aperto e il task che lo possiede.
  - Per segnalare un bug: aggiungi LOG=RAM:nfs-handler.log alla riga
    Startup, riproduci il problema e invia il log.


8. Strumenti inclusi
--------------------

  C/NFSDismount    DEVICE/A,KEEPSEG/S   smontaggio pulito (invia ACTION_DIE)
  Tools/nfsls      SERVER/A,EXPORT/A,PATH,UID/N,GID/N,WRITETEST/S
                   client NFS di prova indipendente (elenca una directory)
  Tools/NotifyTest PATH/A,SECS/N,INITIAL/S  stampa le notifiche DOS
